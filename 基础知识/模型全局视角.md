## 一、这些技术在模型的什么位置

一个大语言模型本质上是一个"积木堆叠"结构，一层 Transformer Block 重复几十次：

```
输入 Token
   │
   ▼
┌─────────────────────────────┐
│  Token Embedding            │ ← 埋层：把 token 变成向量
├─────────────────────────────┤
│  ┌─── Transformer Block ×N ─┐│
│  │                          ││
│  │  ★ 注意力层 (Attention)   ││ ← MLA / GQA / 线性注意力 /
│  │    + RoPE 位置编码        ││    Sliding Window 都在这里
│  │                          ││
│  │  ★ 前馈网络 (FFN / MoE)  ││ ← SwiGLU / 稀疏化 / 专家混合
│  │                          ││
│  └──────────────────────────┘│
├─────────────────────────────┤
│  RMSNorm / LayerNorm         │ ← 归一化（散布在块内）
├─────────────────────────────┤
│  输出层 (lm_head)            │ ← 预测下一个 token
└─────────────────────────────┘

推理时的"外挂"系统（不在模型权重里，但决定体验）：
  ★ KV Cache 管理 ← PagedAttention / KV量化 / MLA压缩
  ★ 采样策略      ← temperature / top-p
  ★ 加速技术      ← 投机解码 / Continuous Batching
```

所以听到的技术可以分成两大类：

- **改模型结构的**（MLA、MoE、线性注意力）→ 影响训练和推理
- **不改结构、只优化推理的**（PagedAttention、投机解码）→ 部署侧技术

## 二、发展时间线：每个技术解决什么危机

Transformer 的历史就是一部"哪里疼医哪里"的历史：

| 时间    | 技术                                            | 解决的危机                                          |
| ------- | ----------------------------------------------- | --------------------------------------------------- |
| 2017    | **Transformer / MHA**                           | RNN 无法并行训练（源头）                            |
| 2019    | **MQA**                                         | KV Cache 显存爆炸 → 多头共享一份 KV                 |
| 2020    | **GPT-3 规模定律**                              | 发现"堆参数"这条路有效                              |
| 2021    | RoPE 成为主流                                   | 绝对位置编码外推差                                  |
| 2022    | **FlashAttention**                              | 注意力计算显存瓶颈（不改变数学，只优化访存）        |
| 2023    | **GQA**（Llama 2-70B 采用）                     | MQA 质量损失太大 → 折中方案                         |
| 2023    | **Mamba / RWKV / RetNet**                       | 注意力 O(n²) 复杂度 → 线性递归路线                  |
| 2024.05 | **MLA**（DeepSeek-V2）                          | KV Cache 仍太大 → 把 KV 压缩进低秩潜空间            |
| 2024.12 | **DeepSeek-V3**：MLA + MoE + 无辅助损失负载均衡 | 训练成本大降                                        |
| 2025    | **混合架构**（Qwen3-Next 等）                   | 纯线性注意力丢信息 → 3:1 交错"线性层 + 1层全注意力" |
| 进行中  | 深度思考（o系列 / R1）、测试时扩展              | 从"堆参数"转向"堆推理时间"                          |

**关键洞察**：MLA 和线性注意力是两条并行的路线——

- MLA 是"把全注意力做便宜"（保留精确注意力，压缩缓存）
- 线性注意力是"换一种便宜的近似"（牺牲精确性换 O(n) 复杂度）
- 当前共识是**混合使用**两者。

## 三、技术家族树

### 家族 1：注意力机制（核心）

```
注意力机制
├── 精确注意力（每对 token 都算相似度，O(n²)）
│   ├── MHA   —— 多头注意力，始祖，每个头独立 KV
│   ├── MQA   —— 所有头共享 1 份 KV（省显存，质量降）
│   ├── GQA   —— 分组共享（Llama 2/3、Qwen 用它）✓ 生产主流
│   ├── MLA   —— 把 KV 投影到低秩潜向量再缓存（DeepSeek 独创）
│   │           KV Cache 缩小到 MHA 的 1/10 以下，质量不降反升
│   └── 变体：Multi-head Latent + 窗口注意力（混合）
│
├── 线性注意力（O(n) 复杂度，可处理超长序列）
│   ├── RWKV     —— 最早出圈的可并行 RNN 式路线
│   ├── RetNet   —— 微软提出，推理时退化为递归
│   ├── Mamba    —— 选择性状态空间模型（SSM），2023 最热
│   │   └── Mamba-2（SSD 理论，和注意力统一了数学框架）
│   ├── GLA      —— 门控线性注意力
│   └── DeltaNet —— 固定容量的"神经记忆"思想
│
└── 混合架构（2025 的共识答案）
    └── 例如 Qwen3-Next：每 4 层中 3 层用线性注意力 + 1 层用 GQA
        —— 线性层负责"日常信息传递"，全注意力层负责"远距离精确检索"
```

**发展方向：MQA → GQA → MLA 是"KV Cache 减肥三部曲"；Mamba/RWKV 是"造新引擎"；混合架构是"两台引擎都要"。**

### 家族 2：其他结构组件（同属一个 Block 内）

| 位置     | 技术                         | 作用                                                         |
| -------- | ---------------------------- | ------------------------------------------------------------ |
| 位置编码 | RoPE、YaRN（外推扩展）       | 让模型知道 token 顺序；YaRN 让 8K 训练的模型跑 128K          |
| FFN 层   | SwiGLU 激活                  | 现代模型标配（Llama、Qwen、DeepSeek 全用）                   |
| FFN 层   | **MoE（专家混合）**          | 把大 FFN 拆成多个专家，每次只激活少数 → 参数大、计算省（Mixtral、DeepSeek-V3、Qwen3 有 MoE 版） |
| 归一化   | RMSNorm、Pre-Norm            | 训练更稳，已是标配                                           |
| 整体结构 | 深窄 vs 宽浅、Embedding 共享 | 影响性价比                                                   |

### 家族 3：推理侧技术（不改权重，改服务）

| 技术                       | 解决什么                                            |
| -------------------------- | --------------------------------------------------- |
| **FlashAttention 1/2/3**   | 让注意力算得快、省显存（数学不变，改 GPU 访存模式） |
| **PagedAttention（vLLM）** | KV Cache 显存管理，像操作系统管内存页一样管缓存     |
| KV Cache 量化              | 缓存从 FP16 压到 FP8/INT4                           |
| 投机解码                   | 小模型起草、大模型验证 → 生成加速 2-3 倍            |
| Continuous Batching        | 多用户请求打包调度，吞吐量翻倍                      |

### 家族 4：训练与对齐（另一条主线）

```
预训练（Next Token Prediction）
    → SFT（监督微调）
    → RLHF / DPO（对齐人类偏好）
    → 推理时扩展（o1 / R1 的 CoT 强化学习，2025 热点）
```

## 四、用 DeepSeek-V3 串一遍（学以致用）

当听说 "DeepSeek-V3 = MLA + DeepSeekMoE + MTP + FP8"，翻译过来就是：

| 技术                     | 所在位置 | 效果                                                 |
| ------------------------ | -------- | ---------------------------------------------------- |
| **MLA**                  | 注意力层 | KV Cache 缩小 ~10 倍 → 推理便宜                      |
| **DeepSeekMoE**          | FFN 层   | 6710 亿参数但每 token 只激活 370 亿 → 训练和推理便宜 |
| **MTP（多 Token 预测）** | 输出层   | 训练信号更密集 + 可用于投机解码                      |
| **FP8 训练**             | 数值精度 | 训练省钱                                             |

**现代大模型设计的统一哲学：参数可以大，每个 token 的计算和显存必须小。**

MLA 管显存，MoE 管计算，混合注意力管长序列——三者殊途同归。

## 五、2026 年最新进展：混合注意力之后又出现的新技术

混合注意力（2025 的答案）已经不是最前沿——2026 年它进化成了更复杂的形态。

### 注意力层本身的三条新路线（2025末~2026）

| 路线 | 代表技术 | 思路 |
| ---- | -------- | ---- |
| **学习式稀疏注意力** | DSA（DeepSeek V3.2 首创）→ 各家跟进：QSA（千问）、MSA（MiniMax）、LSA（美团 LongCat） | 训练一个轻量"索引器"给历史 token 打分，每个 query 只对 Top-K 位置算精确注意力 |
| **压缩注意力** | HCA/CSA（DeepSeek-V4）、文心 5.5 的 HCA+MLA | 把每 128 个 token 压缩成 1 条缓存"摘要"，大部分层只看摘要，少数层精读原文 |
| **混合线性注意力** | Kimi KDA + MLA、千问 GDN + GQA（3:1） | 线性层管日常传递，少量全局层管精确检索 |

**关键趋势：三条路线开始融合**。最新模型（GLM-5.3-Flash、Qwen3.8-Flash-Next、DeepSeek-V4.1-Flash）同时用两种以上技术，2026 年的"Flash/Pro 拆分"产品策略也源于此。

### 注意力层之外的一批新技术（2026 年新增）

| 位置 | 新技术 | 说明 |
| ---- | ------ | ---- |
| 残差连接 | **mHC**（流形约束超连接）、**AttnRes** | 残差从"1条通道"升级为"4条并行流"，深层信号更稳；K3 甚至让当前层跨层检索历史表示 |
| 训练优化器 | **Muon** | 正在取代 AdamW 成为新标配（DeepSeek/智谱/千问/Kimi 已采用），收敛更快 |
| 数值精度 | **FP4 原生训练 + FP4 KV Cache** | DeepSeek-V4 专家权重 FP4、KV 缓存 890 字节/token（比 V1 少 437 倍） |
| 记忆系统 | **条件记忆**（Engram、n-gram 哈希表） | 每 token O(1) 查表，放在内存而非显存——这是"第五个趋同点" |
| KV 管理 | **跨层 KV 复用**（IndexShare/IndexCache） | 2026 年独有的新方向：相邻层共享缓存，5 个新模型已采用 |
| 工程侧 | **KV 缓存翻译**、HALO 蒸馏 | 不同架构模型之间直接移植缓存（不用重读上下文）；把已训练的 Transformer 低成本改造成混合模型 |

## 六、2026 年优化方向的转变：北极星指标变了

2026 年最大的变化不是某个技术，而是**行业竞争的坐标系换了**：

| 维度 | 2023-2025 | 2026 |
| ---- | --------- | ---- |
| 卖点 | 参数量、跑分第一 | **单位成本下的有效智能**（每个 token 的有用产出） |
| 核心瓶颈 | 训练算力 | **推理成本**（Agent 输入输出比约 150:1，输入 token 主导成本） |
| 核心指标 | benchmark 分数 | bytes/token（每解码一个 token 搬多少显存字节）、长任务完成率 |
| 驱动力 | 聊天/写作 | **Agent**：动辄百万 token 上下文、数百次工具调用、长时程任务 |

一切新技术的终极目标：**把长上下文的推理成本曲线拉平**（DeepSeek-V4.1-Flash 做到 1M 上下文的解码算力只比 4K 多 25%）。

背景数据：中国日均 token 调用量两年涨了 1400 倍，Agent 推理计算量两年涨了 1 万倍——谁把解码做便宜，谁就赢得 Agent 时代。

## 七、各家发力方向（2026 实况）

### 开源阵营（架构创新主战场）

| 厂商 | 最新模型 | 发力方向 |
| ---- | -------- | -------- |
| **DeepSeek** | V4 / V4.1-Flash | 最激进：压缩+稀疏+滑窗三合一，mHC、Muon、FP4、Engram 记忆，主打"重写长上下文成本曲线" |
| **Kimi（月之暗面）** | K3（2.8T，1M 上下文） | 混合线性（KDA + 门控 MLA 3:1）+ AttnRes，押注 Agent 长任务 |
| **Qwen（阿里）** | Qwen3.8 系列 | GDN 混合 3:1 + 超稀疏 MoE（512 选 10），Flash-Next 是 Qwen4 预览（线性+稀疏双开） |
| **智谱 GLM** | GLM-5.3 | 旗舰走 MLA+稀疏+跨层复用；Flash 版直接做到 1M 上下文每 token <1GB 读取 |
| **百度** | 文心 5.5 Flash（2026.11.5 发布） | HCA+MLA（1:7）、未来 token 预测 ECHO、新型分词器，同尺寸 SOTA |
| **MiniMax** | M3 | 自研 MSA 块稀疏，1M 上下文下计算量降到前代 1/20 |
| **蚂蚁百灵** | Ling/Ring 2.5 | 万亿参数混合线性 + 思考模型，1:7 混合比，访存压到 1/10 |
| **腾讯/美团/小米** | Hy4 / LongCat-2.0 / MiMo | 各自的稀疏注意力变体；美团甚至推出"输入缓存命中不收费" |
| **Meta** | Muse Spark Open | 反而保守：仍是 GQA+SWA，加了个 LatentMoE |
| **NVIDIA** | Nemotron 3 | Mamba-2 + 仅 8 层注意力，走 SSM 路线 |

### 闭源阵营（不拼架构拼系统）

| 厂商 | 最新 | 发力方向 |
| ---- | ---- | -------- |
| **OpenAI** | GPT-5.6（Luna/Terra/Sol 三档，1M 上下文） | 架构不公开。主推 **Agent 原语**：持久化推理、原生上下文压缩、多智能体编排、程序化工具调用（让模型写 JS 代码在上下文外处理数据）。核心哲学："每个 token 挤出更多有用工作" |
| **Anthropic** | Claude Fable 5 / Opus 5 | 质量与编码王座（SWE-bench 97%）；发力产品化 Agent（Cowork、Skills、MCP 协议——已成行业标准） |
| **Google** | Gemini 3.7 | 通用 Agent + 智能模型路由（简单任务小模型、难任务大模型，主动降成本） |

**一个有意思的对比：开源拼的是"把注意力做便宜"，闭源拼的是"把 token 用得少"**——殊途同归，都是降单位成本。
